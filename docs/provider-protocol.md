# Provider core protocol

This document defines the implementation contract between the Go notification core, the existing Node agent runtime, and the local UI. Agent sessions are the business identity. Platform groups and topics are private provider implementation details.

## Components

- `native/core`: Go executable `nootify-core`; owns providers, notification-session mappings, delivery records, Feishu WebSocket ingestion, and authenticated gRPC remote connections.
- The Node service retains existing agent input transports, CLI compatibility, settings UI, GitHub, and desktop lifecycle. It starts the core as a private stdio child. Production never starts the legacy Feishu history poller.
- Provider types are `feishu` and `remote`. Both can have multiple named instances. A remote instance connects to another Nootify; that remote server broadcasts unhandled incoming events to every independently subscribed downstream.
- `native/tailscale` retains the embedded Tailscale identity. Private RPC tunnels and published listeners let the core use that identity without depending on the operating system Tailscale installation.

## Identity and content

A session is `{node_id, adapter, session_id, name?, metadata?}`. `node_id` is a core-generated stable UUID. The bridge fills a missing local node ID. Existing hostname bindings are adopted during migration without changing the original agent session ID.

A message reference contains `{origin_node_id, provider_id, message_id}`; optional `thread_id` preserves the original Feishu reply thread as return-route context without changing message identity. Provider IDs belong to their originating node. The reference survives every relay and durable replay unchanged. Resolving a legacy message ID or a three-field reference recovers retained thread context, and acknowledgement must not erase it.

Content is `{text?: string, blocks?: ContentBlock[]}`. Blocks use `{type, text?, url?, children?}` and support at least paragraph, text, link, and code. Providers must reject unsupported blocks rather than silently discard them. Plain text uses `{text}`. Depth and block shape are validated before serialization or text flattening; flattening uses a single builder so nested blocks do not repeatedly copy accumulated text. The normalized incoming event carries both this content and a text representation for existing agent adapters.

## Private stdio RPC

Remote RPCs are bounded to 45 seconds within a 60-second core command deadline. The stdio bridge waits 65 seconds, and the HTTP client waits 75 seconds, so outer transports do not cut off a live inner operation. Unknown submission outcomes keep their durable request identity and are never blindly resubmitted with a new ID.

The process starts with `--state-dir <private directory>`. It emits a ready frame `{id:0,result:{ready:true,node_id}}`. Requests are NDJSON `{id:number,method:string,params:object}`; responses are `{id,result}` or `{id,error:{code,message}}`. Request handling must be concurrent: an operation waiting for an agent delivery or outbound tunnel must not prevent completion RPCs from being read. Stdout is exclusively protocol data. Protocol writes use a bounded queue, and cancellation interrupts owned pipe IO even if the parent stops draining output. EOF cancels the service and closes network connections.

Methods:

- `status` -> `{node_id,providers:ProviderSummary[],default_provider_id?,remote:RemoteSummary}`.
- `provider.save` accepts a provider config, generates an ID if absent, and returns its redacted summary. Config: `{id?,name,type,connection_type?,enabled,app_id?,app_secret?,recipient_open_id?,address?,token?,tls?,server_name?}`. Feishu `connection_type` is `bot` or `personal-app`; transport `type` remains `feishu`. Omitted subtypes preserve existing values; older missing values display as Bot without writing on reads. Remote providers reject this field. Blank/omitted existing secrets preserve their values. Existing provider types and Feishu App IDs are immutable, including disabled/unbound instances and configuration imports; create a new provider to use a different app. Same-app secret rotation is supported. `address` is host:port for remote providers. Direct nonlocal connections require TLS; plaintext is limited to numeric loopback or the verified private embedded encrypted bridge. Tailnet names and arbitrary loopback forwarding endpoints alone do not prove protected transport. An omitted enabled flag means true.
- `provider.delete` accepts `{id}`; deletion is persisted and closes that instance. It must not delete agent conversations.
- `provider.default` accepts `{id}`.
- `remote.configure` accepts `{enabled,listen,token?,tls_cert_file?,tls_key_file?}`. Default listen is `127.0.0.1:9418`. A token is generated if needed. Default is disabled. Reject an unsafe public plaintext listener; public listeners require certificate/key TLS. Return a redacted remote summary.
- `remote.secret` -> `{token}`. Only explicitly authorized local UI/control callers may invoke it.
- `remote.identity` -> `{node_id,public_key}`. The base64 Ed25519 public key is safe to exchange; the private signing key stays in the core's private state.
- `remote.peer.bind` accepts `{node_id,public_key}` to pin an existing legacy peer through the private local control path. A different already-pinned key is rejected. Neither identity-management method is callable over gRPC.

Listener configuration and imports prepare the candidate socket and TLS certificate before persisting changes. Bind, TLS and pre-commit persistence failures retain the previous live listener and configuration; committed durability warnings reconcile the live listener to the published state. The same address can reload a certificate while preserving authenticated streams; changing its TLS mode requires disabling it first. Token rotation retains the socket but cancels RPCs admitted under the previous token generation.
- `session.ensure` accepts `{provider_id?,session}` -> `{provider_id,session,created,chat_id?,thread_id?}`. Reuse an existing provider binding; otherwise use the requested/default provider. Remote requests preserve the originating session identity.
- `session.ensure` additionally accepts `automatic:true` for background enrollment; automatic requests cannot reactivate tombstones, including through remote relays.
- `session.list` returns an array of bindings `{provider_id,session,created,chat_id?,thread_id?,sender_open_id?,deleted?,delete_pending?}`. Tombstones are included; compatibility callers filter them.
- `session.bind` accepts `{provider_id?,session,chat_id,sender_open_id}` to validate and adopt an existing Feishu group without replacing conflicting routing metadata.
- `session.metadata.get` / `session.metadata.set` accept `{provider_id?,session,metadata?}`.
- `session.delete` accepts `{provider_id?,session}`. It is idempotent. Feishu's documented already-dissolved application code `232009` completes cleanup; invalid IDs, permission errors and uncertain/transient failures do not prove deletion. Preserve a tombstone so event replay cannot recreate a deleted session. Explicit ensure can reactivate it after proven cleanup.
- `message.send` accepts `{provider_id?,session,content,request_id?}` -> `{message:MessageRef,chat_id?,message_id}`. Without an explicit ID, the core retains one durable attempt for the same provider/session/content while its outcome is unresolved or proven retryable; a completed send allows a later identical intentional send. An explicit ID remains idempotent.
- `message.reply` accepts `{message?:MessageRef,message_id?:string,content,request_id?}` -> `{message:MessageRef,message_id}`.
- `message.ack` accepts `{message?:MessageRef,message_id?:string}` -> `{status:"session_acknowledged",message_id,acknowledged_at}`. Feishu uses a reaction. A plain message ID must fail if ambiguous.
- `delivery.complete` accepts `{delivery_id,status,transport_status?,error?}`. Status is `delivered`, `retryable`, `unconfirmed`, or `rejected`.
- `delivery.retry` accepts `{delivery_id}` and permits explicit retry only of a proven-safe retryable delivery. Its request context governs gate waiting, state transition and dispatch.
- `delivery.inbox.consume` accepts `{message:MessageRef}` after the last corresponding local polled inbox entry is durably consumed.
- `delivery.inbox.reconcile` accepts `{pending:[{inbox_id,message:MessageRef}],before}` -> `{reconciled:true,canceled:MessageRef[]}` to reconcile a durable local inbox snapshot without consuming newer queued deliveries. Canceled entries are removed only by exact sent snapshot ID and full source identity after durable cancellation proof; Node acknowledges only after its deletion commits. These two methods are private to Node.
- `message.inbox.release` accepts `{message:MessageRef}` and durably releases a consumed inbox's holds along every retained upstream path. Progress survives failure/restart and only idempotent control operations are retried.
- `message.inbox.status` accepts `{message:MessageRef}` -> `{consumed:boolean}` for canonical completion reconciliation of unused broadcast branches. It is not an agent message operation.
- `event.active` accepts `{event:Event}` -> `{active:boolean}` and follows retained routes to the authoritative origin before dispatching a remote resource's queued input. A cached relay cannot authorize stale work while the source is unreachable; the delivery remains retryable. Origin-signed `activity_proof` (protobuf field 10) binds full session/event/message/thread identity, content, sender and immutable chat incarnation under the origin's stable Ed25519 key. After source payload/reference compaction, that proof plus an active exact binding preserves valid downstream backlog. Before its first upgrade retention sweep, the origin snapshots compact signatures for retained source events and already-signed source references into `legacy_activity_proofs`. This one-time evidence lets the origin validate already-confirmed legacy relay frames that lack their own proof, even after normal payload/reference GC and restart. Missing legacy evidence is unavailable, not cancellation; retired resources and altered proofs fail closed.
- `config.export` returns a private credential-inclusive backup `{version:1,providers,default_provider_id?,remote}`. The local bridge writes this only to a private export file.
- `config.import` accepts that backup, validates it before applying it, and never imports node identity, session state, or delivery state. A retained provider ID must keep its existing type; a type change rejects the import before state mutation. Imported compatibility credentials refresh the local legacy API/directory clients without rewriting the imported provider instances.
- `dial.complete` accepts `{request_id,address?,error?}`.
- `transport.configure` accepts `{tailnet_enabled:boolean}`. When enabled, remote dials to Tailscale IPs or `.ts.net` hosts request an embedded tunnel from the Node bridge.
- `migration.import` accepts `{app_id,app_secret,recipient_open_id?,connection_type?,legacy_host,bindings:[{chat_id,app_id?,session_id,adapter?,session_name?,history_cursor?}]}`. Node resolves missing adapters from saved sessions before sending the migration and carries only whole-chat history progress. Multiple groups for one session remain independent aliases, with their own chat IDs and trusted senders. An existing enabled same-app provider owns imported bindings when available; otherwise import once into `legacy-feishu`. Never overwrite a later provider edit or deletion. No credentials means no import. A matching known legacy `connection_type` may fill only missing subtype metadata on same-app stored providers, even after the original migration completed; explicit subtypes, credentials, bindings, defaults, and tombstones remain unchanged.

Outgoing async events:

- `{event:"delivery",data:{delivery_id,session,message,content,text}}`: only emitted for a target whose node ID equals this node's ID. The core persists pending state before emission; it does not treat bridge receipt as agent acceptance. Node calls existing agent transport and completes the delivery with its actual outcome. A resumed uncertain submission must not be automatically submitted again.
- `{event:"dial",data:{request_id,address}}`: bridge opens a Tailscale tunnel and returns its owner-restricted local endpoint, network and capability through private `dial.complete`.

- `{event:"log",data:{status,provider_id?,message_id?,error?}}`: no credentials or auth headers.

Trae and WorkBuddy queue the original input plus the structured provider message reference. Reading their inbox renders callback commands with the current Node/CLI location, state directory and HTTP port, so restarts and relocation do not preserve stale command paths. Thread context and opaque reference fields survive persistence. Legacy Feishu source records remain supported; ordinary source-free inbox text is unchanged.

## Public summaries and local UI API

`ProviderSummary` contains `{id,name,type,connection_type?,enabled,status,error?,app_id?,recipient_open_id?,address?,tls?,server_name?,secret_set?,token_set?}`. Feishu summaries identify `bot` or `personal-app`; remote summaries omit `connection_type`. Never include application secrets or tokens.

`RemoteSummary` contains `{enabled,listen,status,tls,token_set,tls_cert_file?,tls_key_file?,peers:[{node_id,name?,connected_at,connected,pending,last_ack?,public_key?,identity_status}]}`. Peer identity status is `pinned` or `unbound`. TLS file paths are non-secret configuration; omitted paths and tokens are preserved on edit. Never include token or private-key contents.

The Node UI adds:

- `GET /ui/api/providers` -> the `status` object plus `{editable:boolean}`.
- `POST /ui/api/providers` with `{action:"save",provider:ProviderConfig}`, `{action:"delete",id}`, or `{action:"default",id}` -> fresh status plus editable.
- `POST /ui/api/providers` also accepts `{action:"reconnect",id}`. It reuses the selected channel's private stored configuration and does not switch defaults.
- `POST /ui/api/providers/registration` accepts `{action:"start",name,enabled,id?}` for a personal app. An existing `id` must already be personal and subsequent authorization must return the same App ID. New authorization allocates a separate channel and leaves existing/default channels unchanged. Status and cancellation require `{action:"status"|"cancel",registration_id}`. Another tab cannot retarget an active flow. Responses contain sanitized `LarkRegistrationPage` plus `registration_id` and the completed `provider_id`; no device code or app secret reaches the browser. A saving operation refuses cancellation; completed saves remain queryable. `save_unconfirmed` reports an unknown save outcome and its allocated channel ID without automatic resubmission. Confirmed-save warnings retain completion.
- `POST /ui/api/providers/setup` accepts `{id}` and checks that specific Feishu app's messaging scopes. These registration/setup endpoints require local access and the UI request header even for reads; GET is not supported, and tailnet callers cannot obtain QR authorization links.
- `GET /ui/api/settings/remote` -> remote summary plus `{node_id,editable}`.
- `POST /ui/api/settings/remote` with remote config -> fresh remote summary plus node ID and editable.
- `POST /ui/api/settings/remote/secret` -> `{token}`.

Direct local browser pages can edit without an owner capability. Provider mutations and secret reads require a loopback socket peer on the local listener plus the existing Host/origin/Fetch Metadata/UI-header checks. Remote listeners remain read-only for settings even when their proxy connects over loopback. Local processes are trusted by this policy; general control APIs still require their bearer. The native desktop and `ui-url` CLI create an independently owned gateway origin serving trusted packaged assets. Browser capability keys arrive only in the gateway URL fragment, are immediately removed from the visible URL, and remain in memory. No authorization cookie or persistent browser storage is used; cookies are host/path scoped and are not isolated by TCP port.

Browser-to-gateway and gateway-to-daemon requests and responses use AES-GCM authenticated frames, including streamed directory results. Frames bind session ID, fresh request nonce, direction and response index; replayed requests, altered/truncated responses and expired sessions fail closed. Daemon bootstrap uses a dedicated TCP connection and fresh mutually authenticated HMAC transcript (30-second challenge lifetime). Its traffic key is derived locally with domain separation from the private PSK, full transcript and public session ID/expiry; bootstrap never transmits that key or the root bearer, even to an active forwarding relay. Browser/gateway keys are independent. There is no plaintext fallback or automatic mutation resubmission after interruption. Gateways expire after two idle minutes or eight hours; reload requires a fresh CLI/native authorization. Native mode pins the live owned origin and recreates it after child exit or failed navigation. General `/v1/` control calls still require the actual bearer and are not exposed through the gateway. Gateway reconnect authorization is single-flight. Each issued transport is retained until revoked, and close waits for in-flight authorization so a late capability is also revoked. Only idempotent revocation may be attempted after a broken transport; ordinary operations remain blocked. Gateway close revokes its daemon capability through authenticated `/ui/api/auth/revoke`; abandoned sessions reclaim capacity after three idle minutes, with authenticated activity refreshing that lease. Authenticated input-validation failures remain encrypted and do not invalidate an otherwise valid session. Tailnet settings summaries remain read-only and omit credentials and authorization URLs. Direct local summaries are editable. Tailnet repository follow changes and pull refreshes retain their existing server-authorized POST paths; direct local pages can edit without a URL capsule and retain access after reload. UI strings support Simplified Chinese and English.

Navigation adds `Providers` under message bridging. The sidebar's `GitHub` group becomes `Repos`. Settings' Feishu entry is replaced by Remote access (`远程接入`); Feishu configuration lives in each provider editor. Agents remain agent input configuration. Remote access displays listening configuration and the independently subscribed downstream peers.

## Subscription identity and trust

Each core keeps its existing node UUID and a private Ed25519 signing identity. Subscribe requires the listener bearer plus a Hello containing the node ID, name, and public key. The server sends a fresh 32-byte challenge; the client signs the domain-separated server ID, client ID, name, public key, and challenge. No peer queue, replay, or confirmation is exposed before verification. The first successful subscription of a new node durably pins its public key. Other bearer holders cannot impersonate that pinned node or replay captured proofs. Multiple proven subscriptions for one node still share its queue.

Existing peers without a pin remain `unbound` and cannot consume their retained backlog. On the downstream, run `node-identity`; verify the public identity out of band, then run `peer-bind --peer-node-id <node-id> --public-key <public-key>` locally on the upstream. Both endpoints must be upgraded for the challenge protocol. Existing queues, cursors, pins, and node UUIDs survive restart and token rotation.

The proof protects subscription replay and confirmations. General unary `Call` retains the shared-bearer trust model: a listener token grants session/message operations to trusted peers and does not provide complete per-node authorization. Use distinct listeners/nodes for mutually untrusted callers. TLS remains required for public plaintext-unsafe listeners. Connection setup and subscription proof are bounded to five seconds; inactive HTTP/2 connections expire after 30 seconds. A healthy authenticated subscription can stay idle indefinitely.

## Routing and persistence

Feishu ingress requires a retained, nondeleted binding for the same app/chat and its trusted sender. Description markers alone cannot authorize a new session. Legacy ingress revalidates current descriptions and announcements; conflicting routes fail closed. Explicit adoption always checks both sources, including an already managed description and reused binding, and never overwrites a human-written description or announcement. Its validation requests must provide fresh parseable source-time evidence; missing or malformed dates return `unavailable` instead of manufacturing an epoch history boundary from an empty or stale cache. Structured session metadata is retained locally for such groups. The compatibility endpoint accepts/translates `metadata:"announcement"` from old CLIs without replacing structured metadata, while unsupported `pin:true` and `metadata:"message"` fail explicitly.

Feishu receives events over WebSocket. Startup/reconnection reconciles each retained resource from a persisted cursor to a captured finite endpoint, with pagination and source/reference deduplication. Failed attempts retry that same interval with cancellable backoff (250 ms to 30 seconds, 45 seconds per attempt); successful synchronized connections perform no periodic history polling. Only completed finite coverage for one chat advances that chat's cursor; successful live input never jumps every chat by local wall clock. An absent cursor receives only a safe baseline before an actual history scan; failed live source timestamps and retained retryable admissions extend its lower bound, so initialization itself cannot acknowledge an unscanned failed event. Accepted live input and failed bound live ingestion both coalesce event-triggered coverage for that chat, keeping long healthy connections reclaimable and safe retries recoverable without an idle polling loop. Persisted boundaries are capped by Feishu `CreateTime` or API `Date` evidence, with an inclusive one-second source-time overlap for header precision; a fast local clock is only a query hint, never checkpoint authority. A pre-create history boundary and post-publication scan cover messages sent after invitation but before the binding's create response. Later live input cannot skip an unresolved gap. Source creation timestamps keep deduplication records protected until the corresponding history cursor covers them, so available history is not truncated by the ordinary seven-day completed-record horizon. Platform retention, permissions and unavailable history remain explicit recovery failures.

Only unmatched events are broadcast. Matching uses the full session identity, not just a local agent ID. Locally owned offline/failed sessions are not rerouted as unmatched. Invalid/unauthorized events are rejected at ingress. Every peer has its own bounded delivery window, durable cursor into the shared broadcast ledger, confirmations, and reconnect replay. A full window does not reject other peers' broadcasts; that peer refills its window from the retained backlog independently. Global storage limits remain explicit admission failures. One peer's confirmation cannot consume another peer's event. Keep stable event IDs, origin provider references, hop limits and visited-node information to stop loops and duplicate local execution across multiple routes.

Session operations use per-session synchronization; deletion is serialized with ingress and explicit retry through delivery emission. Acknowledgements for the same full message reference are serialized through provider RPC and persistence, while unrelated messages can proceed independently. Suppressed hop-exhausted/visited copies cannot install return routes or references. No node-wide operation lock is held while calling a remote provider. Multiple streams from the same downstream node share that node's durable queue and confirmations without replacing one another. A hop-exhausted or already-visited copy that was not handled does not suppress a later valid route for the same event.

Session operations, message sending, replying, metadata and deletion follow their selected provider binding and return path. With multiple retained upstreams, return routing prefers a connected provider before submission; it never switches routes automatically after an uncertain reply. They are not broadcast commands. Delete notification resources and mappings only, never an agent's original conversation. Retired-resource cancellation snapshots are offered before data backlog on each subscription, remain durable independently of source-event confirmations, and propagate through relays. Control frames include optional protobuf `cancellation_json`; both ends must understand the cancellation protocol. Remote input also checks authoritative origin activity before local dispatch, so offline stale relays fail closed. Cancellation terminalizes only known undispatched/queued work and releases its holds; actually pending or unconfirmed submissions preserve their evidence. Local queued-inbox cancellation proof remains retained until Node durably removes and acknowledges the exact canceled entries, including crash/restart repair. Multiple feeds from the same bot must not independently execute the same source message.

A temporary state file is flushed before atomic replacement. Directory sync completes the durability barrier; a later failure reports `committed_not_durable`, with the committed memory/file state preserved and live configuration reconciled to it. This maps to HTTP 409, never a pre-submission 503. `Store.Sync()` retries only durability, not the business operation. A pending intent without confirmed durability cannot submit to a provider or local agent. Admission first retains retryable no-submission proof, then arms a pending intent only after its barrier succeeds. If that barrier fails, exact-record repairs restore safe retryability without calling the provider; queued repairs flush before later admission, writes, sync or orderly close. If the filesystem rejects every repair write and the process is forcibly terminated, the unpersisted proof cannot survive: restart conservatively retains an unknown outcome. Peer publication uses a durable snapshot, so downstreams never observe a hold whose origin publication is still uncertain. Core-pipe disconnect after submission is unconfirmed; failure proven before submission is unavailable. A gRPC authentication rejection before command dispatch preserves safe rejection proof. Unknown agent/provider acceptance is never blindly retried.

Completed eligible event/delivery/operation records retain at least seven days of deduplication; references retain at least thirty days, refreshed on use/consumption. Missing legacy ages get a full grace period. Pending, uncertain, retryable, queued inbox, independent peer backlog, unresolved source history and unfinished release obligations never expire to make room. Bindings, tombstones, pins and cursors remain durable. Reusing an ID after its terminal retention horizon is a new admission. Capacity/byte limits reject admissions if only protected or within-horizon work remains. The one-time `legacy_activity_proofs` migration retains signatures without payloads or callback routes outside time-based GC, under an explicit entry limit and the existing state byte cap. A persisted empty map marks migration complete, so later traffic and restarts cannot continuously grow this compatibility ledger. Source evidence already absent at upgrade cannot be reconstructed and remains unavailable.

`delivered/inbox_queued` is still outstanding for retention. Full-reference holds preserve callback routes and source deduplication at every hop until durable consumption. Release progress is recorded per upstream path, including later alternate routes, and recovered after restart. Unused broadcast siblings reconcile canonical completion rather than pinning unrelated completed traffic forever. Maintenance prioritizes releases, bounds each sweep to eight references/five seconds, persists route rotation before network I/O, limits each route attempt to one second, and probes old non-owner holds only after seven days with bounded backoff; actual owner pending input is never cleared by such probes. These control probes do not poll Feishu messages or resubmit agent input. Upstream ingestion acknowledgement remains distinct from downstream and agent acknowledgement. Shutdown stops accepting new deliveries and drains accepted input while the core can still record outcomes. Network publication failures appear separately from committed provider/remote/import results; uncertain publication is not blindly retried.

## Embedded Tailscale RPC additions

Requests retain the helper's existing flat `{id,method,...fields}` format:

- `tunnel` with `{address:"tailnet-host:port"}` -> `{id:string,network:"unix" | "npipe",address:string,token:string}`. Local endpoints are owner-restricted Unix sockets (`0600` socket in `0700` directory) or Windows named pipes with a protected owner-SID-only DACL, first-instance and remote-client restrictions. Core verifies endpoint ownership/permissions, including the connected pipe's owner/DACL, before sending credentials. TCP endpoint completions are rejected, so another local user cannot occupy the handshake queue through a discovered loopback port. The token is a per-allocation 256-bit capability encoded as 64 lowercase hex characters; it travels only through private helper/core IPC, including `dial.complete`, and is neither persisted nor exposed by public summaries. Before HTTP/2/TLS bytes, core sends the exact versioned frame `NOOTIFY-TUNNEL/1 <token>\n` and waits for byte `0x01`. The helper verifies the frame in constant time before embedded-identity dialing or authenticated-slot admission. Missing/wrong/allocation-mismatched capabilities fail closed. `close_tunnel` with `{tunnel_id}` closes the listener and connections.
- `publish` with `{port:number,target:"127.0.0.1:port" | "[::1]:port"}` -> `{port}`; listens on that Tailscale port and forwards raw TCP to the numeric loopback target. It must not inject the existing HTTP PROXY preamble into gRPC. `unpublish` with `{port}` closes it.

All listeners and connections close on EOF/shutdown. Publication and tunnel handles belong to one helper process: intentional disable, enrollment cancellation, logout, and helper failure invalidate those handles. Re-enabling must publish the configured listener and create tunnels in the replacement helper. Disabling downstream access only withdraws its listener publication and preserves outgoing provider tunnels. Provider save/delete/import reconciles tunnels against enabled Remote addresses, retaining shared addresses and retrying failed cleanup; pending dials share one allocation and cannot reintroduce a removed address. Changing to a listener that cannot be reached through numeric loopback withdraws the previous Tailnet publication before reporting the new configuration; failed withdrawal retains its handle for retry. IPv4-mapped IPv6 Tailnet addresses are unmapped before transport selection. Existing port-80 browser proxy behavior and peer verification remain intact.

Raw connections have a shared cap of 128. Each active tunnel/publication reserves two guaranteed slots, shares a 32-slot burst pool, and has a maximum of 16 connections; at most 32 tunnels and 16 publications are admitted. Pending tunnel handshakes use a separate two-connection budget per tunnel (at most 64 total), with a three-second absolute deadline. They cannot trigger upstream dialing or consume authenticated raw slots. OS endpoint restrictions deny unrelated local users before this queue; capability authentication remains defense in depth for accepted local connections. Successful authentication clears the deadline. HTTP/PROXY connections retain their independent 128-connection limit. Raw forwarding preserves half-close and healthy idle streams. Unexpected listener Accept failure retains its reservation and retries binding with cancellable exponential backoff from 100 ms to five seconds; existing streams remain intact. Closing or replacing a bridge cancels recovery.

Legacy thread sends and metadata reads may omit the adapter. The Node bridge resolves the full local identity from core notification-session bindings, optionally scoped by provider, and rejects ambiguous IDs instead of assuming a default agent adapter.

## Validation

Exercise at least two downstream clients receiving the same event, independent acknowledgements, local ownership stopping broadcast, multiple hops and loop deduplication, offline-peer reconnect replay, provider-scoped identity, deletion and retry semantics, secret redaction, remote authentication, and actual rich-text conversion. Verify provider CRUD and remote access in the browser at desktop/mobile sizes and both appearances. Existing agent transport regressions must keep passing.
